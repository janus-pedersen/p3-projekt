\subsection{Requirements}
Based on the background and state-of-the-art section, a couple of requirements were made. These outlined the product and the accompanying system. Afterwards, in the problem analysis section, the final requirements were made. Those requirements drew from the UML diagrams, such as context and deployment diagram. Which was used to create an overview of the system, its ability, the hardware parts and how it all fit together. 

\subsection{System architecture}
In terms of system architecture, a choice had to be made in terms of hardware. Based on the collective knowledge and idea of what the product should be able to do, there was a need for the microcontroller to have Bluetooth and an accelerometer. Furthermore, there was a wish for an all-in-one product, so that the final product would be small in size. The need for it to be small was because the vision of the product being a wristband was already there. This is why the microcontroller ESP32C6 dev board was chosen. This, along with a 3.7-volt battery, concludes the hardware. For the software, the Arduino IDE was used along with C++ code for the microcontroller, whereas for the application, VS Code with Typescript using the React framework was used. 

\subsection{Testing}
In order to make sure that the system was functioning in accordance with the requirements, a list of tests was made. Firstly, the battery of the wristband was tested by making multiple voltage tests. The algorithm was tested through testing performance metrics, by making a sensitivity analysis, a specificity test, and thus conducting the accuracy test. To test the application code, a line of unit tests was written in order to validate the functions and features. Another test that was conducted was a user test, in which it was tested how intuitive the workings of the wristband and application were. Furthermore, an integration test was created to test the entire app, as if it were a user using the app.
