It supports the two distinct views described in the design section (see \autoref{fig:wearer_pages} and \autoref{fig:guardian_pages}). Instead of importing a larger navigation framework for this limited use case, a lightweight custom solution was implemented.

The system is based on two dictionaries, one for each view, where each key–value pair represents a page within that view. Navigation is handled by tracking the current view and page, and updating the variables used to index the dictionaries whenever a page transition occurs.

\subsubsection{Database Connection} \label{sec:database-connection}

The \textit{Firestore} database is setup in a way where a collection can have a number of documents, and a document can have a set of collections and so on. A single document can then be referenced with a \textit{'reference'} (see \autoref{fig:database-reference}). A reference is just a type of file path, describing what collection, what document and so on.

\subsubsection{Contacts}
The user needs to have the ability to add their friends and family as their emergency contacts. To make this as easy as possible, the app makes use of the contact list stored on the users device. From here the user can choose to import a contact, and it will auto fill their information. There is of course also a way to add them manually, but even here, if it finds a contact with the same number in your contacts, it will auto fill the name and image with that found in the contacts list.

\subsubsection{Connecting to wristband}

To connect to a Lapsus Wristband, the user must find the device in the device page, and press connect. This will then create a connection between the two that will stay alive, even when the application is pushed to the background. The app will receive updates whenever the wristband \textit{notifies} the device, this is where it handles the different types of alerts and forwards it to the backend.

It also keeps listening to make sure that the device stays connected, and if ever it becomes unresponsive, the user will be alerted with a notification.

When a wristband is connected, the device page switches from a "connect your device" page, to more of a "configure your device" (see \autoref{fig:device_page}). Although currently, the only information available at the moment is the battery percentage.


\subsubsection{\gls{gps} updates}
To allow allow the relatives to see a history of where they have been, the app needs to capture the location of the device, even when the user has the app in the background. This presented some challenges, as most native systems won't allow permanent location tracking due to battery consumption and privacy concerns. The real solution would be to move the \gls{gps} module to the wristband, as that would increase the precision of the location if eg. the user was in their garden and the app reported the location to be indoors, as that was where they left their phone. Due to the prototype nature of our current solution, it was the easiest to just use the \gls{gps} from the device, as that still provides a general idea of where the user is located.

Both Android and iOS have luckily thought of this, and provides a way to listen for \gls{gps} updates natively. It wakes up a small part of the app to handle the update, giving us just enough time to upload it to our database to display to the relatives.
